# Icons `:icons:core` is the icon sub-framework: a typed reference model, a librsvg renderer,
and one composable. `icons-packs/<pack>/` holds the per-library configs, `icons-plugin/` is the
Gradle plugin that turns an upstream SVG dump into Kotlin. `:framework` knows nothing about
icons — the icon module depends on the framework, not the other way round. ```
icons/core           IconStyle / IconPack / IconRef / Icon() / librsvg cache ← library
icons-packs/lucide   iconsPack { … } config + generated catalog + SVG data    ← library
icons-plugin         sync + codegen Gradle plugin (included build)            ← build logic
``` Dependency direction: `shell-app → icons-packs:lucide → icons:core → framework`. ## Using icons Add the pack you want to the shell: ```kotlin dependencies { implementation(project(":icons-packs:lucide")) // implementation(project(":icons-packs:material-symbols")) } ``` Then reference icons by name — nothing else is needed, no registry, no resource loading: ```kotlin import dev.knshell.compose.Icon import dev.knshell.icons.lucide.Lucide Icon(Lucide.Home, size = 22, color = c.bg) Icon(Lucide.Power, size = 16, color = c.accent, transitionMs = 180) Icon(Lucide.Search, strokeWidth = 1.5) // thinner line, same asset ``` `Lucide.<Name>` is a property, so completion lists the whole catalog and a typo is a compile
error, not a blank pixel. ## API reference ### `Icon(icon, modifier, size, color, transitionMs, strokeWidth)` `dev.knshell.compose.Icon` (in `:icons:core`, so it sits next to the rest of the DSL). | Parameter | Default | Meaning | | --- | --- | --- | | `icon` | — | `IconRef` — `Lucide.Home`, or `Lucide.of("home")` for a runtime id | | `modifier` | `Modifier` | normal modifiers (`onClick`, `pointerCursor`, `align`, margins …) | | `size` | `24` | logical px; the widget pins itself to size×size exactly like `Image`, so a `Row` cannot stretch it | | `color` | `null` | tint written into the pack's `tintAttribute`; `null` = the pack's own colors | | `transitionMs` | `0` | animate a `color` change over N ms (OutCubic, same curve as `animateFloatAsState`); `0` repaints immediately | | `strokeWidth` | `null` | override the pack's default `stroke-width` | Rendering is a `GtkDrawingArea` whose draw function hands the cairo context to librsvg;
`transitionMs` runs inside a frame loop and mutates the node directly, so a colour tween costs
zero recompositions. Icons are painted at device resolution: HiDPI stays crisp, no per-size
asset variants. ### `IconRef` / `IconPack` / `IconStyle` ```kotlin data class IconRef(val pack: IconPack, val id: String) { val style: IconStyle get() = pack.style val source: String? get() = pack.svgInner(id) } interface IconPack { val name: String val style: IconStyle fun svgInner(id: String): String? // raw SVG body, no <svg> wrapper } data class IconStyle( val tintAttribute: String = "stroke", // "stroke" | "fill" val strokeWidth: Double = 2.0, val viewBoxSize: Double = 24.0, ) ``` A hand-written pack is just those three members — the plugin generates them, but nothing
requires the plugin (useful for one-off in-house icons): ```kotlin internal object MyPack : IconPack { override val name = "MyIcons" override val style = IconStyle(tintAttribute = "fill", viewBoxSize = 48.0) override fun svgInner(id: String) = when (id) { "logo" -> "<path d=\"…\"/>"; else -> null } } val Logo: IconRef get() = MyPack.ref("logo") ``` ### Failure behaviour | Situation | What happens | | --- | --- | | id not in the pack (`Lucide.of("nope")`) | warns once to stderr `[icons] … lookup failed …`, paints an empty slot, never throws | | pack never synced | the module does not compile (generated catalog is missing) — the failure is at build time, not runtime | | SVG that librsvg cannot parse | one `[icons] parse SVG lookup failed for '<key>'` line, empty slot | | same icon at two colors | tinted twice, parsed twice at most — results live in a 256-entry LRU keyed `pack:id:color:width` | An un-rendered icon is a visual gap, never a crash: a shell must not die because of an
asset. ## How a pack gets built `./gradlew :icons-packs:lucide:generateIcons` (wired into `compileKotlinLinuxX64`, so a normal
build does it) runs two tasks: 1. **`syncIcons`** — downloads the pinned npm tarball (`-C … --strip-components 1`), finds the directory that
 actually holds the `*.svg` files, and caches it under `.cache/icons/<npm>-<version>/icons`
 (gitignored). A `.synced-version` marker makes re-runs free; bump `version` to re-fetch. Set
 `sourceDir` instead of `npmPackage` to sync from a local checkout. 2. **`generateIcons`** — emits two files into `build/generated/iconPack/kotlin/`: - `<Name>Catalog.generated.kt` — `object <Name>` with **every** catalog id
 (`val Home: IconRef`, `val ids: Set<String>`, `fun of(id: String)`). Complete, so the IDE
 sees all ~2400 icons. - `<Name>Data.generated.kt` — `internal object <Name>Data { fun inner(id) = when (id) … }`
 containing the SVG bodies of the **referenced** icons only, plus the `internal object
 <Name>Pack : IconPack` adapter. Tree-shaken, so an unused icon costs no binary size. Which icons end up in the data file is decided by a source scan (paths, not project
dependencies — no configuration cycle): `Lucide.<Name>` and `Lucide.of("<id>")` occurrences in
`*.kt` under `iconScanRoots`. The roots are declared as real `@InputFiles`, so writing a new `Icon(Lucide.Star)` anywhere re-runs codegen by itself — no `--rerun-tasks`, and no silently tree-shaken icon. References to names outside the catalog are reported: ``` [icons] Lucide: 1 unknown icon reference(s), ignored: Lucide.Hme ``` The scan is deliberately file-based: the shell's own sources are not a Gradle dependency of the
pack, which would create a cycle. ### Naming rules id `home` → property `Home`, `arrow-down` → `ArrowDown`, `wifi-off` → `WifiOff`. The mapping
is the plugin's `NameMapping` and is reversible, which is what lets the scan resolve
`Lucide.WifiOff` back to the `wifi-off` asset. Upstream occasionally collides
(`arrow-down-0-1` and `arrow-down-01` both read as `ArrowDown01`); the generator appends an
ordinal to the later id (`ArrowDown012`) and the scan uses the same table, so the two never
disagree. Ids that would start with a digit (`10k`) get no property — use `Lucide.of("10k")`. ## Adding another pack One config block, no new code. Material Symbols is the reference example because it is a
*fill* pack with a different viewBox — the config absorbs all of that: ```kotlin // icons-packs/material-symbols/build.gradle.kts plugins { alias(libs.plugins.kotlin.multiplatform) id("dev.knshell.icons.pack") } kotlin { linuxX64() sourceSets { nativeMain.dependencies { api(project(":icons:core")) } } } iconsPack { objectName.set("Material") packageName.set("dev.knshell.icons.material") npmPackage.set("@material-symbols/svg-400") version.set("0.49.0") iconsDir.set("outlined") // package/{outlined,rounded,sharp} tintAttribute.set("fill") // solid glyphs, not lines defaultViewBoxSize.set(48.0) // width/height of their canvas defaultViewBoxOverride.set("0 -960 960 960") // their drawing box is offset defaultStrokeWidth.set(0.0) // no stroke geometry } ``` Then `./gradlew :icons-packs:material:generateIcons` and use `Icon(Material.Search)`.
`iconsDir` is a hint: the sync accepts any directory in the tarball that actually holds the
SVGs, so a pack that changes its layout upstream still syncs. ### `iconsPack { }` | Key | Default | Purpose | | --- | --- | --- | | `objectName` | — | generated object / scan anchor (`Lucide`) | | `packageName` | — | package of the generated files | | `npmPackage` | — | npm package carrying the SVGs | | `version` | `latest` | pinned npm version; part of the cache key | | `tarballUrl` | derived | override for non-npm archives | | `iconsDir` | `icons` | preferred SVG directory inside the archive | | `sourceDir` | unset | local directory instead of a download | | `tintAttribute` | `stroke` | attribute that receives the color | | `defaultStrokeWidth` | `2.0` | `stroke-width` for generated documents | | `defaultViewBoxSize` | `24.0` | canvas size the markup is authored for | | `defaultViewBoxOverride` | unset | exact `viewBox` when the box is not `0 0 S S` | | `iconScanRoots` | `framework/src`, `shell-app/src`, `icons-packs` | where usages are searched | | `scanBaseDir` | repo root | base for the roots | | `cacheDir` | `<repoRoot>/.cache/icons` | asset cache | ## Notes and gotchas - **Multicolor packs** (`color` left `null`) are painted as authored. A `fill` pack without an
explicit `color` renders in its literal default (usually black), because `currentColor` is not
resolved from GTK CSS — pass `color = …` for those.
- **Dynamic ids need a literal.** `Icon(Lucide.of(userIcon))` does not pack `userIcon`: only
 string literals are scanned. Ship the candidates by naming them somewhere real, or read
 `Lucide.ids` to check availability first.
- **Doc comments count as usages** — an `Icon(Lucide.Bell)` inside a KDoc example embeds `bell`.
 Harmless, slightly larger data file.
- **Bumping a version is a re-download**, and the old cache directory stays behind; delete
 `.cache/icons/<old>-<version>/` when pruning.
- **Offline builds**: `syncIcons` skips its work while the cache marker matches the pinned
 version, so a pack already synced builds without network. The first sync of a new version
 needs the registry.
- **Renderer is single-threaded by design**: librsvg handles are cached per render identity and
 only touched from the GTK main thread (draw function + composition), so no locking. ## Verification ```bash ./gradlew :icons-packs:lucide:generateIcons # sync + codegen ./gradlew build # everything compiles against the pack ./gradlew :icons:core:linuxX64Test # tint wrapper + LRU behaviour ./gradlew -p icons-plugin test # naming map + collision rules ``` Tests live in `icons/core/src/nativeTest/kotlin/dev/knshell/icons/` (`SvgDocumentTest` for
markup, `RsvgCacheTest` for the cache) and `icons-plugin/src/test/kotlin/` (`NameMappingTest`).
They need no display: a compiled `RsvgHandle` is not a surface, so cache and eviction are
testable headless.
